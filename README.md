# Mini NPU Simulator · 미션 3

표준 라이브러리만 사용해 Cross/X 패턴과 필터의 MAC 점수를 계산하는 Python 콘솔 프로그램입니다. Python 3.8 이상이 필요합니다.

## 파일

- `main.py`: 사용자 입력, JSON 분석, 패턴 생성, 성능 및 최적화 비교 메뉴
- `data.json`: 과제에서 받은 원본 테스트 데이터
- `test_main.py`: 핵심 기능의 자동 회귀 테스트
- `benchmark.py`: 3×3부터 1000×1000까지 2차원/1차원 MAC을 비교하는 재현 가능한 벤치마크

## 실행 방법

PowerShell에서 이 폴더로 이동한 뒤 다음 명령을 사용합니다.

```powershell
python main.py
```

메뉴는 **1 사용자 입력**, **2 data.json 분석**, **3 패턴 생성기**, **4 종료**입니다. 모드 1에서는 직접 3×3 필터를 입력하거나 Cross/X 필터를 자동 생성할 수 있습니다. 모드 3은 N=3~1000의 Cross와 X 패턴을 만들고 자기 패턴이 자기 필터에서 더 높은 점수를 받는지 확인합니다. N이 25보다 크면 전체 행렬 대신 켜진 칸 수만 출력합니다.

`data.json`은 `main.py`와 같은 폴더에 둡니다. JSON 모드는 실행 위치와 관계없이 `main.py`가 있는 폴더의 데이터 파일을 찾습니다.

## 구현과 판정 정책

- `mac()`은 두 겹의 반복문으로 같은 위치의 값을 곱하고 합산합니다. NumPy 등 외부 라이브러리는 사용하지 않습니다.
- `mac_flat()`은 2차원 행렬을 길이 N²의 1차원 목록으로 바꾼 뒤 반복문 MAC을 수행합니다. 평탄화 전처리 비용은 최적화 비교의 측정 구간에서 제외합니다.
- 모든 입력은 정사각 배열, 크기, 숫자 여부, 유한한 값인지 검사합니다. 모드 2는 한 케이스의 오류를 FAIL로 남기고 다음 케이스를 계속 처리합니다.
- `normalize_label()`은 `+`/`cross`를 `Cross`, `x`를 `X`로 바꿉니다. 이 별도 함수 덕분에 JSON 필터 키와 expected 라벨에서 같은 규칙을 재사용하고, 별칭 처리를 한곳에서 확인·시험할 수 있습니다.
- `decide()`는 `abs(score_cross - score_x) < 1e-9`이면 내부 결과를 `UNDECIDED`로 정합니다. 모드 1은 사용자용 `A`, `B`, `판정 불가 (|A-B| < 1e-09)`로 보여주고, 모드 2는 `Cross`, `X`, `UNDECIDED`를 출력합니다. 판정 기준은 같고 표시와 집계만 목적에 맞게 다릅니다.
- 모드 2 요약은 전체/통과/실패와 함께 동점, 판정 불일치, 데이터·스키마 오류를 따로 셉니다. 실패 목록에는 케이스와 이유를 표시합니다.
- 성능 측정은 `perf_counter()`로 MAC 함수 호출만 감싸며 워밍업 1회 후 10회 평균을 냅니다. 입력, 출력, 파일 읽기, 평탄화 전처리는 측정에서 제외합니다.
- 표 너비는 `unicodedata.east_asian_width()`로 계산해 한글과 전각 문자가 있어도 열이 맞도록 출력합니다.
- 입력이 EOF로 끝나면 무한 재입력 없이 현재 작업을 취소하거나 메뉴를 종료합니다.

## 새 라벨 확장 순서

1. `normalize_label()`에 새 표기 별칭과 표준 라벨을 등록합니다.
2. `extract_filter_pair()`의 허용·필수 라벨 집합을 새 라벨까지 포함하도록 확장하고, 중복 별칭 처리를 유지합니다.
3. `decide()`를 여러 점수 중 최댓값 선택 방식으로 확장합니다. 최대 점수가 동률일 때 `UNDECIDED`로 처리하는 기준도 정의합니다.
4. 새 라벨의 사용자 표시, 생성기, JSON 출력이 필요하면 해당 경로를 함께 반영합니다.
5. 라벨 변환, 필터 누락·중복, 단독 최대·동점 최대, 생성 패턴 자가 판정 테스트를 추가합니다.
6. 실제 JSON에 새 expected 및 필터 사례를 넣어 PASS/FAIL 집계를 확인하고 README 스키마를 갱신합니다.

## 결과 리포트

이 저장소의 `data.json`으로 2026-11-17에 프로그램을 실행한 결과입니다. 성능 시간은 실행 기기와 부하에 따라 달라집니다.

현재 데이터에는 6개 테스트가 있습니다. 이전 구현으로 실행했을 때 3개 PASS, 3개 FAIL이었습니다. 실패 ID는 `size_5_1`, `size_13_2`, `size_25_1`이며 세 사례 모두 점수 차이가 `1e-9`보다 작아 동점으로 처리되었습니다. expected는 Cross 또는 X이므로 `UNDECIDED`와 일치하지 않아 FAIL입니다. 이는 입력 크기나 라벨 스키마 문제가 아니라 epsilon 판정 정책의 결과입니다. 현재 구현의 모드 2는 이 동일한 정책을 유지하며 실패 유형과 점수 차이를 요약합니다.

| 크기 | MAC 연산 횟수 N² | 평균 시간(ms, 10회) |
|---|---:|---:|
| 3×3 | 9 | 0.007920 |
| 5×5 | 25 | 0.006100 |
| 13×13 | 169 | 0.035950 |
| 25×25 | 625 | 0.118960 |

이번 한 번의 측정에서는 작은 크기에서 고정 비용과 시간 측정 흔들림 때문에 5×5 시간이 3×3보다 낮게 나왔습니다. 큰 크기까지의 수치는 증가했지만, 이 한 번의 표로 시간과 N²의 정확한 비례를 주장하지 않습니다. `benchmark.py`로 다시 측정할 수 있습니다.

같은 실행에서 평탄화 MAC의 변화율은 3×3 -11.3%, 5×5 -7.7%, 13×13 -9.1%, 25×25 -9.8%였습니다. 변환 시간은 제외한 결과라 실제 전체 처리에서 평탄화가 항상 이득이라고 단정할 수 없으며, 입력 크기와 사용 횟수에 따라 달라집니다.

각 N×N MAC은 N²개 위치를 한 번씩 처리하므로 시간 복잡도는 O(N²)입니다. 표의 연산 수는 9, 25, 169, 625로 증가합니다. 두 분류 점수를 구할 때는 필터 두 개에 MAC을 각각 실행합니다. 작은 크기에서는 함수 호출과 입력 검증의 고정 비용이 눈에 띄므로 실제 시간이 N²에 정확히 비례하지 않을 수 있습니다. 1000×1000 입력은 MAC 1회당 1,000,000개 위치, Cross/X 두 필터 점수는 총 약 2,000,000개 위치 연산을 사용합니다.

FAIL 원인 분류는 다음과 같습니다. 배열 차원 또는 숫자 형식 오류는 데이터·스키마 FAIL, expected 라벨과 계산 결과의 불일치는 판정 불일치 FAIL, epsilon 범위 내 점수 차이는 동점 FAIL로 구분합니다. `+`와 `x` 같은 별칭은 먼저 표준 라벨로 정리하므로 올바른 별칭 표기만으로 FAIL이 발생하지 않습니다. 1e-9 정책은 작은 부동소수점 표현 오차가 승패를 임의로 가르는 일을 막습니다.

### 1000×1000 비용과 최적화

N=1000이면 행렬 하나에 1,000,000개 원소가 있습니다. Python 2차원 리스트는 행 목록과 원소 참조, 숫자 객체를 함께 보관하므로 실제 메모리는 원소 값과 Python 구현에 따라 달라집니다. 입력 행렬과 Cross/X 필터, 파싱된 JSON을 동시에 유지하면 사용량이 더 커질 수 있습니다. 정확한 메모리 및 시간은 아래 벤치마크를 대상 컴퓨터에서 실행해 측정해야 하며, 이 README는 측정하지 않은 값을 결과처럼 제시하지 않습니다.

```powershell
python benchmark.py
```

벤치마크는 미리 생성한 동일 패턴으로 2차원/평탄화 1차원 MAC을 같은 반복 수로 재고 결과 점수도 비교합니다. 이번 환경에서 1000×1000 입력은 2차원 188.001640ms, 1차원 178.215470ms(-5.2%)였습니다. 메모리 사용량은 측정하지 않았습니다. 입력 크기를 직접 지정할 수도 있습니다: `python benchmark.py 1000`. 해당 결과는 한 환경의 단일 실행 표본이며 다른 PC에서 재현되는 보장값이 아닙니다. `array('d')` 등 다른 저장 형식이나 0인 칸 건너뛰기도 측정 전에는 성능 이점을 주장하지 않습니다.

이 미션은 직접 반복문 구현이 조건이므로 벡터화 라이브러리를 사용하지 않습니다. 더 큰 데이터에서는 평탄화가 인덱싱 단계를 줄일 수 있지만, 1차원 복사본은 추가 메모리를 씁니다. 단일 MAC은 각 원소 쌍을 한 번씩만 읽으므로 블록 처리만으로 계산량이 줄지는 않습니다. 데이터가 여러 계산에 재사용되거나 메모리 제한 때문에 전체 입력을 보유하기 어려운 경우에는 행/타일 단위 스트리밍을 고려합니다. CPU의 Python 구현은 인터프리터와 순차 반복 비용을 받고, 최적화된 병렬 NPU는 다수 MAC을 동시에 실행할 수 있습니다. NPU에서도 연산기 수가 늘면 메모리 대역폭, 데이터 공급, 동기화가 병목이 될 수 있어 데이터 재사용과 처리량 균형이 중요합니다.

## 자동 테스트

```powershell
python -m unittest -v
```

테스트는 MAC 결과와 실수 반환, 라벨 표준화, epsilon 동점, 배열 검증, 크기 키 파싱, JSON 케이스 검사, 생성 패턴 자가 판정, 1차원/2차원 결과 일치, 모드 1 동점 문구, 한글 표 너비를 확인합니다.

## 재현 가능한 수동 확인

- 모드 1에서 자동 생성 필터를 선택하고 X 패턴 `1 0 1 / 0 1 0 / 1 0 1`을 입력해 B가 더 높은지 확인합니다.
- 모드 1에서 A와 B에 같은 행렬을 넣으면 `판정 불가`가 표시되는지 확인합니다.
- 모드 1에서 행의 숫자를 두 개만 넣거나 `abc`를 섞으면 해당 행만 다시 묻는지 확인합니다.
- 모드 2에서 여섯 JSON 케이스와 실패 원인별 요약이 출력되는지 확인합니다.
- 모드 3에서 크기 5와 1000을 입력해 자가 판정, 큰 행렬 축약 출력, 성능·최적화 표를 확인합니다.
- 메뉴나 행 입력 중 `Ctrl+Z` 후 Enter로 EOF를 보내면 프로그램이 끝없이 입력을 요구하지 않는지 확인합니다.
