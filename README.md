# Mini NPU Simulator (미션 3)

## 실행 방법

1. Python 3.8 이상을 설치합니다. 설치 화면에서 `Add Python to PATH`를 선택합니다.
2. `main.py`, `README.md`, 그리고 미션에서 별도로 제공한 `data.json`을 같은 폴더에 둡니다.
3. 터미널(명령 프롬프트 또는 PowerShell)에서 이 폴더로 이동합니다.
4. `python --version`으로 버전을 확인합니다.
5. `python main.py`를 실행하고 `1` 또는 `2`를 선택합니다.
6. 데이터 분석 모드가 `data.json`을 찾지 못하면 과제 제공처에서 해당 파일을 받아 같은 폴더에 넣습니다.

## 데이터 형식

첨부 미션 문서는 `filters.size_5`, `filters.size_13`, `filters.size_25` 및 `patterns`의 `size_{N}_{idx}` 키, `input`, `expected` 필드를 요구합니다. 필터 키는 `cross`와 `x`(또는 문서에서 허용한 `+`와 `x`) 형식으로 각 N×N 배열을 담아야 합니다. 예상 데이터의 구체적인 값과 전체 스키마 세부사항은 문서에 실려 있지 않으므로 이 프로그램은 테스트 데이터 파일을 임의로 만들지 않습니다. 제공된 원본 JSON의 구조가 이 형식과 다르면 오류 내용을 확인하고 원본 데이터 설명에 맞춰 조정해야 합니다.

## 구현 요약

- MAC은 표준 라이브러리만 사용하여 두 겹의 `for` 반복문으로 각 위치의 곱을 누적합니다.
- 점수는 실수로 계산할 수 있으며 `abs(score_cross - score_x) < 1e-9`이면 `UNDECIDED`입니다.
- 라벨 비교 전 `+`/`cross`를 `Cross`, `x`를 `X`로 표준화합니다.
- 사용자 입력 모드는 3×3 행마다 열 개수, 숫자 변환, 유한 숫자인지 확인하고 잘못된 줄을 다시 입력받습니다.
- JSON 모드는 각 케이스를 개별 처리하므로 한 항목의 스키마 또는 크기 오류가 다른 케이스 실행을 막지 않습니다.
- 시간 측정은 MAC 함수 호출 구간을 10회 반복한 평균이며 입출력 및 파일 읽기 시간은 포함하지 않습니다.
- 성능 표는 3×3, 5×5, 13×13, 25×25와 N² 곱셈 누산 횟수를 보여줍니다.

## 결과 리포트

실제 제공된 `data.json`으로 2026-11-17에 한 번 실행한 결과입니다. 성능 수치는 컴퓨터와 실행 환경에 따라 달라집니다.
| 크기 | 평균 시간(ms, 10회) | MAC 연산 횟수(N²) |
|---|---:|---:|
| 3×3 | 0.001270 | 9 |
| 5×5 | 0.002890 | 25 |
| 13×13 | 0.016340 | 169 |
| 25×25 | 0.057700 | 625 |

1. 총 테스트는 6개이며, PASS는 3개, FAIL은 3개였습니다.
2. 실패한 케이스는 `size_5_1`, `size_13_2`, `size_25_1`입니다.
3. 세 케이스 모두 크기 키에서 N을 읽었고 필요한 필터와 입력 배열을 정상적으로 불러왔습니다.
4. 모든 배열은 해당 크기의 정사각형이었고 숫자 변환 오류나 크기 불일치는 없었습니다.
5. expected의 `x`와 `+` 표기는 각각 `X`와 `Cross`로 정상 표준화되었습니다.
6. `size_5_1` 점수는 Cross 0.9, X 0.8999999999999999로 출력되었습니다.
7. `size_13_2` 점수는 Cross 7.499999999999997, X 7.5로 출력되었습니다.
8. `size_25_1` 점수는 Cross 4.9, X 4.899999999999999로 출력되었습니다.
9. 각 점수 차이는 1e-9보다 작으므로 epsilon 규칙에 따라 세 결과 모두 `UNDECIDED`입니다.
10. expected가 Cross 또는 X이므로 `UNDECIDED` 결과와 일치하지 않아 FAIL이 되었습니다. 이는 데이터나 스키마 오류가 아니라 명시된 동점 정책에 따른 결과입니다.
11. 남은 세 케이스는 expected 라벨과 더 큰 점수의 필터가 일치해 PASS였습니다.
12. 각 N×N 배열에서 MAC은 N²번 곱하고 누적하므로 입력 크기 N에 대한 시간 복잡도는 O(N²)입니다.
13. 표의 연산 수는 N이 3, 5, 13, 25일 때 각각 9, 25, 169, 625로 증가합니다.
14. 이번 측정 시간은 3×3 0.001270ms, 5×5 0.002890ms, 13×13 0.016340ms, 25×25 0.057700ms였습니다.
15. 측정 시간은 대체로 N² 증가와 같은 방향으로 늘었지만, 한 번의 실행 결과이므로 기기 부하와 타이머 정밀도의 영향을 받습니다.
16. 모드 1은 두 필터에 각각 MAC을 수행하므로 비교에 총 2N² 위치 계산을 사용합니다.
17. JSON 모드 성능 표에서 3×3 입력이 없는 경우에는 시간 측정용 0 배열을 만들며, 이 배열은 미션 테스트 케이스로 집계하지 않습니다.

## 재현 확인

문서 예시의 3×3 Cross/X 행렬을 필터 A/B로 입력하고 Cross 패턴을 넣었을 때 A=5, B=1, 판정 A가 나오는지 확인합니다. 데이터 모드는 실제 과제 제공 `data.json`을 넣어 확인합니다. 잘못된 행 입력 후 재입력, JSON 스키마 불일치의 케이스 단위 FAIL 및 동점 판정을 각각 실제 파일/입력으로 확인한 결과를 제출 전에 기록합니다.
